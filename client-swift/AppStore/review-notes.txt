PocketADM is a client for server software that users run on their own Linux server. It has no backend of ours and no account of its own. Version 2.0 is a native SwiftUI rebuild of the app.

FASTEST ROUTE (no typing, no server needed):
On the first screen, tap "Try the live demo". It signs the app in to a real, running, read-only PocketADM server with sample data and opens the full interface: Dashboard, Containers, Terminal, Assistant and More.

Equivalent manual route: type the address demo.pocketadm.com, tap Continue, and use the password: demo

CAMERA: used only to scan the pairing QR code a PocketADM server prints at the end of its installer, or that a signed-in device shows. "Scan pairing code" asks for camera permission and opens the scanner. The read-only demo cannot create pairing codes, so there is nothing to scan during review; close the scanner with Cancel. "Paste pairing link" accepts the same link as text.

ASSISTANT: an AI agent that works on the user's own server with the user's own API key or coding-agent subscription (Claude Code, Codex, Mistral Vibe). The demo is read-only, so its Assistant tab shows a recorded sample session; sending a message there explains that the demo cannot run the agent.

WATCH AND AI ACCOUNTS: More → Watch shows the channel of the watch, a background agent that checks the user's own server with the user's own AI, with sample messages. Writing to it is disabled in the read-only demo. More → AI accounts shows how a subscription or an API key is connected; in the demo these screens can be viewed but not changed. Signing in to Claude, ChatGPT or Mistral happens on the provider's own website and only connects the user's own server.

NOTIFICATIONS AND BACKGROUND REFRESH: the app asks for notification permission only when the user taps "Turn on notifications" (Watch screen, or More → Watch → settings). Notifications carry messages from the user's own server: its watch, and the assistant waiting for an approval. Push notifications are delivered through PocketADM's relay at pocketadm.com/push, which stores only the push token; where push is not available, background app refresh fetches new messages from the user's server and shows them as local notifications. The demo does not send notifications.

FILES: browsing and opening files works in the demo; creating, uploading, editing and deleting are refused because the demo is read-only.

SERVER OVERVIEW: More → Server overview lists what the demo server runs (domains, services, timers, cron jobs, drives). Opening a service shows its status and log; the start, stop and restart buttons are refused in the read-only demo.

APPEARANCE: More → Appearance switches between themes; the choice is stored on the phone only.

ASSISTANT NOTES AND ATTACHMENTS: More → AI accounts → Assistant behaviour shows the notes the assistant keeps about a server (sample notes in the demo, read-only). The attach button (+) in the Assistant's message field uploads a photo or file to the user's own server, or attaches information from it; it is disabled in the read-only demo.

TERMINAL: in the demo, opening any shell shows a simulated, read-only shell (try ls, docker ps, free, df, cat readme.txt); nothing is executed. On a user's own server it is a real terminal.

APP TRANSPORT SECURITY: arbitrary loads are allowed because PocketADM connects only to servers the user adds, which are often local addresses (192.168.x.x, .local hosts) or VPN addresses. New servers use HTTPS with their own certificate; the app trusts such a certificate only when its key matches the fingerprint in the pairing QR code the user scanned. No traffic goes anywhere other than the servers the user adds.

The app collects no personal data. The push token is used only to deliver notifications.
